🔥 Prometheus — من هو؟

تعريف بسيط

Prometheus هو نظام Monitoring مفتوح المصدر بيجمع البيانات من تطبيقاتك ويخزنها كـ time-series — يعني كل قيمة مرتبطة بـ timestamp محددة.

الفرق الأساسي عن أي database عادية: هو مش بس بيخزن "إيه القيمة" — هو بيخزن "القيمة دي كانت كام في أي وقت".

  • 🏗️بُني عام 2012 في SoundCloud، دلوقتي بـ CNCF
  • 📥Pull model — هو اللي بيجي يسحب البيانات، مش بيستنى حد يبعتها
  • 🗃️بيخزن البيانات locally كـ time-series database (TSDB)
  • 🔎بيتعامل معاه بلغة استعلام اسمها PromQL
  • 🔔بيبعت alerts عبر Alertmanager لما حاجة تعدى الحد
# Prometheus يجمع بيانات زي دي:

# اسم الـ metric + labels + القيمة + الوقت
http_requests_total{method="GET", status="200"} 1523 @1717000000
http_requests_total{method="POST", status="500"} 12 @1717000000

cpu_usage_percent{instance="server-1"} 73.5 @1717000000
memory_used_bytes{instance="server-1"} 52428800 @1717000000

# كل 15 ثانية بيسجل snapshot جديدة
cpu_usage_percent{instance="server-1"} 74.2 @1717000015
cpu_usage_percent{instance="server-1"} 71.8 @1717000030
💬 اشرحها كده
"تخيل إن Prometheus بياخد صورة لحالة السيرفر كل 15 ثانية ويحطها في ألبوم — بعدين تقدر ترجع لأي صورة وتشوف إيه اللي كان بيحصل في أي وقت"

📈 Grafana — من هو؟

تعريف بسيط

Grafana هو منصة Visualization مفتوحة المصدر بتحول البيانات الخام اللي Prometheus بيجمعها لـ dashboards وgraphs تقدر تشوفها وتفهمها بنظرة واحدة.

Grafana مش بيخزن بيانات — هو فقط بيقرأ من Prometheus ويعرضها. زي الشاشة مع الحاسبة.

  • 🎨Dashboards تفاعلية — ممكن تعمل zoom وتفلتر في real-time
  • 🔌بيتصل بأكتر من 50 data source — مش بس Prometheus
  • 🔔Alerting — بيبعت إشعارات على Slack/Email/PagerDuty
  • 👥Team sharing — أكتر من شخص يشوف نفس الـ dashboard
  • 🌐على المتصفح مباشرة — مش محتاج تنصّب حاجة

🎯 إيه اللي بيعرضه Grafana؟

🔢 Stat Panel

📦 أنواع الـ Metrics الأربعة

Counter 🔢

بيتزود فقط — مش بينقص أبداً. زي عداد السيارة.

http_requests_total

⚠️ لو إيه؟ عدد الطلبات، عدد الأخطاء، عدد المستخدمين الجدد

Gauge 📊

بيزيد وبينقص. زي درجة الحرارة.

memory_used_bytes

⚠️ لو إيه؟ RAM، CPU، عدد الـ connections الحالية

Histogram 📉

بيوزّع القيم على buckets ويحسب التوزيع.

request_duration_seconds

⚠️ لو إيه؟ وقت الاستجابة، حجم الـ response

Summary 📋

زي Histogram بس بيحسب percentiles مباشرة.

rpc_duration_seconds

⚠️ لو إيه؟ P50, P95, P99 latency

💬 اشرح الفرق بين Counter وGauge كده
"Counter زي عداد عدد خطوات الـ treadmill — بيزيد بس ومش بيرجع. Gauge زي مقياس السرعة — ممكن يزيد وينقص بحرية."

🌟 الـ 4 Golden Signals

01
⏱️

Latency

الطلب بياخد كام وقت حتى يرجع رد؟
لازم تفرّق بين الطلبات الناجحة والفاشلة.

"ليه الصفحة بطيئة؟"
histogram_quantile(0.99,
rate(request_duration_seconds_bucket[5m]))
02
📶

Traffic

كام request بيجي في الثانية؟
بيحدد حجم الـ load على النظام.

"قد إيه الضغط على السيرفر؟"
rate(http_requests_total[5m])
03
❌

Errors

كام request فشل؟
نسبة الـ 5xx من إجمالي الطلبات.

"في مشكلة في التطبيق؟"
rate(errors_total[5m]) /
rate(requests_total[5m])
04
🌡️

Saturation

السيرفر اتملى لحده؟
CPU وRAM وDisk وConnections.

"السيرفر هيتعب؟"
node_memory_Active_bytes /
node_memory_MemTotal_bytes
💬 اشرح الـ 4 Golden Signals كده
"زي ما الدكتور بيقيس ضغطك وسكرك ودرجة حرارتك وعدد ضربات قلبك — الـ 4 golden signals هم 'فحص طب' لأي سيرفيس. بيديك صورة كاملة عن الصحة."
04 / 05 — Part C

🔎 PromQL — لغة الاستعلام

إيه هي PromQL؟

PromQL (Prometheus Query Language) هي اللغة اللي بتستخدمها عشان تسأل Prometheus أسئلة عن البيانات — زي SQL بالنسبة لقواعد البيانات العادية.

  • 🏷️Labels — بتفلتر النتايج بـ {method="GET"}
  • ⏱️Range — بتحدد الفترة الزمنية [5m] أو [1h]
  • 📐Functions — rate(), sum(), avg(), max()
  • ➕Operators — بتعمل حسابات بين metrics

أمثلة عملية

http_requests_total
كل الـ requests من أول ما السيرفر اشتغل
rate(http_requests_total[5m])
معدل الطلبات في آخر 5 دقايق (requests/second)
sum(rate(errors[5m])) / sum(rate(requests[5m]))
نسبة الأخطاء من إجمالي الطلبات
http_requests_total{status="500"}
فلترة — عارض بس الـ 500 errors
topk(5, rate(requests[1h]))
أعلى 5 services في عدد الطلبات
💬 اشرحها كده
"PromQL زي ما بتكتب 'جيب الطلبات اللي فشلت في آخر 5 دقايق' — بس بلغة Prometheus"
04 / 05 — Part D

🔔 Alertmanager — نظام التنبيهات

إزاي بيشتغل؟

Alertmanager هو الجزء اللي بيتابع الـ rules اللي أنت تحددها — لو حاجة وصلت لحد معين، بيبعتلك notification.

  • 📋تعرّف القاعدة — "لو الـ errors زادت عن 5% لمدة 5 دقايق"
  • ⏰Prometheus يراقب — بيتحقق من القاعدة كل scrape interval
  • 🔔Alert يتشغّل — Alertmanager يشوف ويبعت الـ notification
  • 📲Notification تتبعت — Slack, Email, PagerDuty, SMS
🚨 مثال Alert حقيقي
"High Error Rate on Production!" — نسبة الـ errors وصلت 8% في آخر 5 دقايق على server-prod-1
# rules.yml — تعريف الـ alert rules

groups:
  - name: production-alerts
    rules:

    - alert: HighErrorRate
      expr: rate(http_errors_total[5m]) / rate(http_requests_total[5m]) > 0.05
      for: 5m   # لازم يفضل هيك لمدة 5 دقايق قبل ما يبعت
      labels:
        severity: critical
      annotations:
        summary: "نسبة الأخطاء وصلت {{ $value | humanize }}%"

    - alert: HighCPUUsage
      expr: cpu_usage_percent > 85
      for: 10m
      annotations:
        summary: "CPU عالي على {{ $labels.instance }}"

🛠️ إزاي عملنا Setup النظام؟

# docker-compose.yml — كل حاجة في مكان واحد

services:
  prometheus:
    image: prom/prometheus:latest
    ports: ["9090:9090"]
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml

  grafana:
    image: grafana/grafana:latest
    ports: ["3000:3000"]
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=secret

  node-exporter:
    image: prom/node-exporter:latest
    ports: ["9100:9100"]
    # بيجمع metrics السيرفر: CPU, RAM, Disk

📝 خطوات الـ Setup بالترتيب

  • 1️⃣شغّل Prometheus وGrafana بـ Docker Compose
  • 2️⃣أضف مكتبة prom-client في تطبيقك
  • 3️⃣عمل expose لـ /metrics endpoint
  • 4️⃣أضف تطبيقك في prometheus.yml كـ scrape target
  • 5️⃣افتح Grafana على port 3000 وأضف Prometheus كـ data source
  • 6️⃣اعمل dashboard أو import واحد جاهز
// تطبيق Node.js — expose الـ metrics
const client = require('prom-client');
client.collectDefaultMetrics(); // CPU, RAM تلقائياً

const httpReqs = new client.Counter({
  name: 'http_requests_total',
  labelNames: ['method', 'status']
});

app.get('/metrics', async (req, res) => {
  res.set('Content-Type', client.register.contentType);
  res.end(await client.register.metrics());
});

⚖️ Prometheus vs البدائل

المعيار 🔥 Prometheus + Grafana ☁️ Datadog 📡 AWS CloudWatch
التكلفة ✅ مجاني — open source 💸 $15-23 لكل host/شهر ⚠️ بيتحسب على الـ usage
التحكم ✅ تحكم كامل — على سيرفراتك SaaS — بياناتك على عندهم مرتبط بـ AWS فقط
سهولة الإعداد ⚠️ بتحتاج إعداد يدوي ✅ سهل جداً — install agent ✅ موجود تلقائياً في AWS
Retention ⚠️ 15 يوم افتراضي (قابل للتمديد) ✅ 15 شهر ✅ قابل للتخصيص
Dashboards ✅ Grafana — قوية جداً ✅ ممتازة built-in ⚠️ محدودة نسبياً
💬 لو سألوك: ليه اخترت Prometheus؟
"لأنه open source ومش محتاج ندفع per-host، عندنا تحكم كامل في البيانات، والـ Grafana بتديك dashboards أقوى من أي حاجة تانية. في production scale كبير ده بيفرق كتير في التكلفة."

الخلاصة في جملتين

"Prometheus يجمع ويخزّن بيانات التطبيق كل 15 ثانية — Grafana تعرضها في dashboards جميلة — عشان نشوف المشاكل قبل ما المستخدم يحس بيها"
